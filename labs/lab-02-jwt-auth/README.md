# Авторизація на JWT

## Що це

Реєстрація, вхід і розмежування доступу за ролями `user` та `admin`. Після входу користувач отримує JWT-токен, бачить його розшифрований вміст і таймер до завершення дії, а також може перевірити, як сервер відповідає на запити з токеном, без нього чи з підробленим токеном. Адміністратор керує користувачами: змінює ролі й видаляє облікові записи. Перший зареєстрований користувач стає адміністратором.

## Технології та як це працює

- `api/`: сервер на Node.js 24, TypeScript 7, Express 5, jose (JWT), Zod і pino. Паролі хешуються вбудованим у Node алгоритмом argon2id, користувачі зберігаються у файлі `api/data/users.json`.
- `web/`: клієнт на Angular 22 (signals, Signal Forms, router guards, HTTP interceptor).
- `contracts/`: спільні типи запитів і відповідей для сервера та клієнта.

При реєстрації чи вході сервер підписує токен HS256 секретним ключем. У payload записуються ідентифікатор і роль користувача, автор, група й варіант, а термін дії становить 71 секунду. Клієнт надсилає токен у заголовку `Authorization: Bearer <token>`. Сервер перевіряє підпис, видавця й термін дії, а роль бере з бази, тому її зміна діє одразу. Неавторизований запит отримує 401, а запит без потрібної ролі отримує 403.

## Запуск

Потрібні Node.js 24+, bash і `setsid`. Залежності скрипт встановить сам, Ctrl+C зупиняє все.

- `./run.sh dev` відкривається на http://localhost:4200. Це режим розробки: сервер і клієнт працюють окремо й перезапускаються при змінах коду, логи читабельні, налаштування беруться з `api/.env` (приклад у `api/.env.example`).
- `./run.sh prod` відкривається на http://localhost:3000. Спершу скрипт перевіряє типи й робить оптимізовану збірку клієнта, потім запускає один процес сервера, який роздає і клієнт, і API. Логи йдуть у JSON, налаштування беруться лише зі змінних середовища. Якщо `JWT_SECRET` не задано, скрипт генерує випадковий секрет на час запуску.
