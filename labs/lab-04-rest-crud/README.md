# Технологічні карти на REST API

## Що це

Застосунок для ведення технологічних карт деталей (варіант 11: деталь, вид обробки, тривалість обробки). Технологічна карта описує маршрут обробки деталі: впорядкований список операцій, кожна з яких має вид обробки, обладнання й тривалість у хвилинах. Номери операцій (005, 010…) і сумарна тривалість рахуються автоматично. Для деталей, видів обробки й карт реалізовано повний CRUD: додавання, перегляд усіх записів і одного запису, редагування та видалення. Головна сторінка показує статистику й трудомісткість за видами обробки.

## Технології та як це працює

- `api/`: REST API на Node.js 24, TypeScript 7, Express 5, Mongoose 9 і Zod, логи пише pino.
- `web/`: клієнт на Angular 22 (signals, Signal Forms, httpResource).
- `contracts/`: спільні типи запитів і відповідей для сервера та клієнта.
- `compose.yaml`: MongoDB 8 у Docker-контейнері `kpi-labs-mongo` на порту 27018, дані зберігаються в томі `kpi-labs-mongo-data`.

Дані лежать у трьох колекціях MongoDB: `parts`, `operation_types` і `process_cards`. Операції вкладені в документ карти, а на деталь і види обробки карта посилається за ідентифікатором. Унікальні індекси не дають створити дві деталі з однаковим позначенням, два види обробки з однаковою назвою (без урахування регістру) чи дві карти для однієї деталі. Сервер перевіряє запити схемами Zod і правилами домену, не дає видалити деталь або вид обробки, які використовуються в картах, і відповідає кодами 201, 204, 400, 404, 409 і 422, а коли база недоступна, кодом 503.

Ресурси API: `/api/parts`, `/api/operation-types` і `/api/process-cards` (GET і POST для колекції, GET, PUT і DELETE для `/:id`), а також `/api/statistics` і `/api/health`.

## Запуск

Потрібні Node.js 24+, Docker із Compose, bash і `setsid`. Скрипт сам встановить залежності й запустить контейнер MongoDB, якщо той ще не працює. Ctrl+C зупиняє все, а також контейнер, якщо його запустив скрипт.

- `./run.sh dev` відкривається на http://localhost:4200. Це режим розробки: сервер і клієнт перезапускаються при змінах коду, логи читабельні, налаштування беруться з `api/.env` (приклад у `api/.env.example`), а порожня база заповнюється демонстраційними даними.
- `./run.sh prod` відкривається на http://localhost:3000. Спершу скрипт перевіряє типи й робить оптимізовану збірку клієнта, потім запускає один процес сервера, який роздає і клієнт, і API. Логи йдуть у JSON, налаштування беруться лише зі змінних середовища.
